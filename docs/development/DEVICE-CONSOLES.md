# K08 장비 콘솔 초안

이번 초안은 기존 교육용 콘솔의 기능을 운영 장비의 작업 흐름으로 정리한다. 사용자의 첫 피드백을 받기 위한 구현이며, Community 출시 완료를 뜻하지 않는다. 화면은 공통 Core 로그인 아래 `/core/#fw/policies`, `/core/#ips/policies`, `/core/#waf/policies`에 위치한다.

## 화면과 기능

- 왼쪽에서 방화벽·침입 방지·웹 방화벽·SIEM·접근 제어·계정·감사 화면을 선택한다. README의 로고를 공유한다.
- 방화벽 기본 화면은 FORWARD 필터 정책이다. 이름·주소·서비스 검색, 동작 필터, 순서 변경, 활성/비활성, 편집·삭제를 제공한다. 시스템 경로 정책은 잠금 표시와 함께 읽기 전용으로 보여준다.
- 주소·서비스 객체, NAT, 전체 규칙, 이벤트, 변경 이력은 별도 탭이다. 전체 체인의 명령 출력은 편집 폼 옆에 상시 표시하지 않는다.
- 오른쪽 편집 패널에서 입력하고 `검증 및 검토`를 누르면 실제 장비 문법 검사를 실행한다. 변경 전후 설정을 확인하고 `변경 적용`으로 반영한다.
- IPS는 프로토콜·주소·포트·검사 영역·문자열/정규식·동작·임계값을, WAF는 검사 대상·연산자·패턴·변환·단계·심각도·차단 응답을 제공한다.
- 실습 설명·과제 채점·점수 화면을 장비 운영 화면에 넣지 않는다. 외부 사용자 평가는 아직 진행하지 않았다.

## 원본 재사용

`~/pjt/{nft,suricata,modsec}_edu_gui/server.py`에서 순수 규칙 생성 함수를 선별 이식했다. kt66 벤더 파일의 해시도 [출처 기록](../provenance/console-source.json)에 남긴다. 기존 서버·훈련/채점·에이전트 설정 API는 복사하지 않는다. 네트워크/테이블 이름, 엄격한 입력 검사, 원자적 적용, 공통 인증과 새 화면은 xOC 프로파일에 맞춘다. 원본 프로젝트 파일과 실행 환경은 수정하지 않는다.

## 적용 범위와 안전한 변경

| 장비 | 사용자 정책 범위 | 검증·적용 |
|---|---|---|
| 방화벽 | `inet xoc_policy` FORWARD, 주소/서비스 set, `ip xoc_nat` NAT | `nft -c`, 해당 두 테이블만 한 batch로 교체 |
| IPS | 기본 probe 규칙과 별개인 사용자 규칙 파일 | 후보 설정 `suricata -T --init-errors-fatal`, blocking `reload-rules` |
| WAF | 8080 웹 서비스 vhost의 사용자 규칙 | 후보 파일로 `apache2ctl -t`, 성공 시 graceful reload |

방화벽 사용자 정책에서 허용해도 후속 시스템 경로 필터가 적용된다. 이 프로파일의 기본 웹 서비스는 8080이며, 다른 목적지나 포트를 새로 개방하는 장비 프로파일 편집은 이번 초안에 포함하지 않는다. NAT도 후속 필터와 라우팅이 충족되어야 통신한다. 관리 접속 8443은 사용자 정책에서 보호한다. IPS 사용자 규칙은 관리 포트를 제외하며, WAF 사용자 규칙은 실습 웹 vhost에만 적용한다. 기존 관리 경로의 기본 보안 검사와 Wazuh 편집 예외는 유지한다.

장비별로 하나의 Unix socket 작업을 순서대로 처리한다. Core 프로세스의 UID를 확인하며 TCP API나 Docker socket을 제공하지 않는다. 장비는 자기 네트워크 namespace와 자기 설정 볼륨만 변경한다. 관리 플랫폼에는 장비 정책 파일 쓰기 권한을 주지 않는다.

미리보기는 실행 중인 설정을 바꾸지 않는다. 적용권은 2분 유효한 검토 토큰·작업자·버전에 묶고, 새로운 미리보기는 이전 토큰을 대체한다. 적용 전 다시 문법 검사를 하며 reload 실패 시 이전 설정으로 되돌린다. 이전 버전 복원도 새 검토/적용을 거친다. 최근 20개 이전 설정을 장비 볼륨에 보존한다.

조회자는 조회만, 관리자·운영자는 검토가 가능하다. 실제 적용은 장비 쓰기 허용 상태에서만 가능하며 잠금 변경은 관리자에게만 허용한다. 모든 변경 요청은 먼저 Core 감사에 기록한다. 장비의 별도 영속 journal과 설정 버전은 적용 결과·복원 결과를 남긴다. 장비 적용과 Core DB는 단일 트랜잭션이 아니므로 응답이 실패한 경우 현재 버전과 장비 이력으로 결과를 확인한다.

## 선택 설치와 후속 경계

기본 설치에 `console-fw`, `console-ips`, `console-waf`를 포함한다. 각각 `--without console-fw` 등의 옵션으로 제외할 수 있다. 관리 UI를 제외해도 관리 기반의 장비 상태 볼륨과 적용 정책은 유지된다. 다시 선택하면 같은 정책을 사용한다. 별도 포트 개방·추가 계정·수동 Docker 설치는 필요하지 않다.

전체 장비 프로파일 편집, 자유 텍스트 명령 실행, 시스템 체인 변경, 대량 규칙 처리, 모든 종류의 PCRE 이스케이프 편집은 제공하지 않는다. 임의 시스템 규칙 삭제나 전체 ruleset flush를 허용하지 않는다. K10 전체 제거/실패 복원과 K11 장기 부하·백업·복구는 기존 출시 게이트로 남긴다.

Suricata reload 동작은 [공식 rule reload 문서](https://docs.suricata.io/en/suricata-8.0.3/rule-management/rule-reload.html)를 따른다. [검증 실행 결과와 실제 화면](K08-VALIDATION.md)을 함께 기록한다.
