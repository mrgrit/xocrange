## 개발을 진행하면서 먼저 해결할 것

### 1. 로컬 Git 연결

현재 `/home/ccc/xocrange/.git`은 이 세션의 파일시스템 권한에서 읽기 전용이고, `git status`는 초기화된 저장소로 인식하지 못한다. 따라서 이 위치의 Git 초기화·커밋을 완료했다고 할 수 없다. `.git`의 보호 설정을 변경하거나 우회하지 않았다.

이 제한은 현재 작업공간의 Git 메타데이터 쓰기에 적용된다. 원격 기록은 쓰기 가능한 별도 체크아웃에서 커밋·푸시할 수 있으므로 개발·공유를 중단할 이유는 아니다. 현재 디렉토리에서 로컬 Git 명령을 사용하려면 저장소 연결이 가능한 환경에서 작업공간을 열어야 한다. 일반 소스·문서 작성은 현재 디렉토리에서 가능하다.

### 2. 기준선 확장과 소스 검토

kt66 작업 트리에 수정·미추적 파일이 남아 있다. 계획의 19개 파일 보존은 완료했으나, 이식할 실제 파일 집합을 K02의 의존 그래프로 확정한 뒤 전체 후보를 보존해야 K01의 이식 기준선이 완성된다. 기존 소스에 직접 리브랜딩·구조 변경을 적용하지 않는다.

### 3. 지원 환경과 통합 테스트 VM

현재 개발 호스트 관측값은 Ubuntu 22.04.5 / x86_64 / Python 3.10.12 / Docker CLI 29.6.1 / Compose 5.3.1이다. 이는 **관측한 개발 환경**이며 제품 지원 버전을 확정한 것은 아니다. Docker daemon 연결·컨테이너 기동·자원 가용성은 이번에 검증하지 않았다.

단위·계약 개발은 지금 진행할 수 있다. 실제 fw·ips·web 및 netglue 검증에 들어가기 전에는 별도 Linux VM 또는 격리된 runner를 확보한다. 기존 kt66의 Docker socket·포트·네트워크·볼륨을 통합 시험에 연결하지 않는다. 지원 OS/아키텍처/런타임 버전과 최소 자원은 K01/K05에서 검증하고 K11에서 측정 근거를 정리한다.

### 4. 첫 계약과 검증 자료

C1 v0.1과 Suricata EVE·ModSecurity JSON·nftables syslog fixture가 첫 기능 개발 대상이다. `tenant_id`, `range_id`, 안정된 이벤트 ID, 발생/수집 시각, 원본 참조, 탐지와 차단의 구분을 고정한다. 그다음 manifest·의존성 검사·Compose 생성기의 첫 조각을 구현한다.
