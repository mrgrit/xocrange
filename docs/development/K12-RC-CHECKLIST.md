# K12 Community RC 체크리스트

정본: [CORE-KICKOFF §7 G1](https://github.com/mrgrit/xocrange_plan/blob/f548caa/docs/CORE-KICKOFF.md). 이 문서는 G1의 각 증거 항목에 대해 **지금까지 있는 실행 증거**와 **RC 판정 전에 남은 일**을 정리한다(작성 2026-11-13, 기준 커밋 `5e38777`).

## 판정 원칙

- RC 증거는 **하나로 고정한 후보 커밋**에서 다시 실행한 결과만 센다. 아래 "기존 증거"는 이전 소스의 결과이며, 그 항목이 실행 가능하다는 근거일 뿐 RC 증거가 아니다.
- "코드 존재"와 "실행 검증"을 구분한다. 단위 테스트만 있는 항목은 실행 검증으로 세지 않는다.
- 이 VM(Claude Code가 실행 중인 개발 VM)에서는 재부팅·빈 OS 설치를 할 수 없다. 해당 항목은 별도 VM이나 사용자 조작이 필요하다.

상태: **있음**(이전 소스로 실행 검증, RC 후보로 재실행만 필요) · **부분**(일부 조합·조건만 검증) · **없음**(실행 증거 없음) · **결정 필요**(기술 검증이 아니라 소유자 결정)

## RC를 막는 항목

실행 증거가 없거나 소유자 결정이 필요한 항목이다. 나머지는 RC 후보로 재실행하면 된다.

1. 기본 전체 구성의 빈 VM 한 번 설치 (별도 VM 필요)
2. RC 후보 재부팅 검증 (이 VM 재부팅 또는 별도 VM)
3. 외부 PC 출처 IP 보존 (외부 PC 필요)
4. 배포물 경계 자동 점검 스크립트
5. 전체 디스크 고갈 시험과 24시간 이상 장기 운영 기록
6. 동시 apply 시험
7. 선택 조합 보완: `console-fw`·`console-waf` 개별 제외, "전체 Community"·bootstrap·기본 타깃 제외의 범위 정의
8. Core 배포 라이선스·프로젝트 자산 배포 권리 결정 (소유자)
9. 릴리스 노트·사용자 안내·SIEM 포함 권장 사양

## 이 VM에서 바로 할 수 있는 것

- 4 경계 점검 스크립트 작성·실행
- 5의 장기 운영 기록 시작(DB 크기·수집 지연·메모리를 주기적으로 남김)
- 6 동시 apply 시험 작성·실행
- 7 콘솔 개별 제외 조합(`xoc module remove/add`)
- 저장 효율(이벤트당 저장량) 설계

1·2·3·8은 사용자 조작이나 별도 환경이 필요하다.
