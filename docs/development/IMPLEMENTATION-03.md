# 단일 실행 설치기 · 세 번째 구현

기준일: 2026-11-07. 사용자 요구에 따라 Linux만 설치된 VM에서 한 번 실행으로 의존성 설치·구성·기동·검증을 수행하는 설치기를 추가했다.

이 문서는 최초 설치기 작성 당시의 기록이다. 이후 원격 접속을 확보해 수행한 실제 설치·통신 검증은 [VM 검증 기록](VM-VALIDATION-2026-11-07.md)에 기록한다.

## 구현

- 루트 `install.sh`: Ubuntu 26.04 전용 VM 점검, 기본 패키지와 Docker 공식 apt 패키지 자동 설치, 모듈 계획, 스토리지와 네트워크 전제 조건, 이미지 빌드·기동·수용 검사, 부팅 서비스.
- `scripts/install-support.py`: 공개 소스 파일 집합의 해시 사본, 기존 사본 무결성 검사, Docker/containerd 설정 보존과 데이터 경로 생성.
- `lab start`: 검증된 계획과 로컬 이미지로만 기동하며 자동 build/pull 금지.
- 설치 성공·실패 단계와 실제 수용 증거를 root 전용 상태·로그에 기록. 현재 완료 범위는 experimental security-path이며 전체 Community 완료는 false.
- Suricata 설정 생성에 필수 `%YAML 1.1` 문서 헤더 누락을 수정. [공식 로더](https://github.com/OISF/suricata/blob/main/src/conf-yaml-loader.c)가 이 헤더를 요구한다.

## 검증

**로컬 테스트 120개 통과.** 셸 구문, 설치 미리보기와 설치 소스 사본 생성도 확인했다. 테스트는 비공개 파일 제외, 소스 변조·symlink 거부, 기존 스토리지 자동 이관 거부, 컨테이너 런타임 설정 보존, 부팅 시 이미지 build/pull 금지, Suricata 문서 헤더를 포함한다.

설치 소스 사본에서 생성한 Compose 문법 검사와, 생성한 Docker/containerd 설정의 각 실행 파일 검증 모드도 통과했다. 이 검사는 호스트의 실제 설정을 변경하거나 데몬을 시작하지 않는다.

실제 원격 VM은 SSH 연결 시간 초과로 접근하지 못했다. VM에 패키지·Docker를 설치하거나 호스트 설정을 변경한 사실은 없다. **빈 Ubuntu에서 설치, 이미지 빌드, 실제 통신·차단, 재실행, 재부팅 검증은 아직 대기 중이다.** 코드와 단위 테스트를 전체 설치 성공으로 간주하지 않는다.
