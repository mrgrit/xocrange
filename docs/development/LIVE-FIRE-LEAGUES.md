# Live Fire 개인 훈련과 교수자 리그 설계

상태: **설계만 반영, 실행·채점·리그 API는 미구현**. Core의 아카데미 실습 노트와 Live Fire의 정식 답안 제출을 구분한다. 콘텐츠는 동일한 15개 시나리오를 사용하며, 실행 엔진은 tw2를 연결한다.

## 학습 경로

| 구분 | 아카데미 | 개인 Live Fire | 교수자 리그 |
|---|---|---|---|
| 시작 | 강좌의 차시 열기 | 시나리오 선택 → 내 훈련 시작 | 교수자 개설 → 초대/코드 → 참가 → 준비 |
| 작성 | 글·명령·전체 출력·여러 캡처를 배치하는 차시별 노트 | 현재 미션 답안을 작성하고 등록 | 지정 라운드·역할의 미션 답안을 작성하고 등록 |
| 중간 저장 | 자동 임시 저장 + 지금 저장 | 미션별 비공개 초안 | 본인 미션별 비공개 초안 |
| 평가 | 작성 완료 표시, 점수 없음 | 등록한 답안만 채점, 개인 피드백 | 등록한 답안만 채점, 리그 규칙에 따른 순위·피드백 |
| 열람 범위 | 본인 노트 | 본인 훈련·결과 | 교수자는 담당 리그, 학생은 본인/허용된 팀과 공개 순위 |

아카데미의 노트를 읽거나 자동 저장했다고 공방전 답안이 제출되지 않는다. 연계 공방전 링크는 시나리오 설명으로 이동한다. 정식 연결 후 설명 화면에서 **혼자 훈련 / 리그 참가**를 선택한다. 노트를 근거로 가져오려면 학생이 내용·캡처를 선택하고 제출 전에 확인한다. 원본 노트를 공개하거나 점수로 변환하지 않는다.

## 개인 훈련

학생에게 허용된 시나리오를 골라 별도 환경을 생성한다. 같은 학생의 반복 시도도 서로 다른 실행 ID·증거 범위를 갖는다. 1인 훈련은 Red → Blue → Purple 단계를 순서대로 수행한다. 반대편 역할을 자동 수행해야 하는 시나리오는 교관이 검증한 재현 절차를 준비하며, 임의의 AI 공격을 기본값으로 삼지 않는다.

미션별 흐름은 **초안 작성 → 등록 → 채점 대기 → 결과·근거·피드백**이다. 초안은 재접속 시 이어 쓸 수 있지만 점수와 리더보드에 영향을 주지 않는다. 등록한 답안은 불변 스냅샷이며 수정 제출은 별도 시도다. 연습 모드의 재시도 횟수·힌트·정답 공개 정책을 시작 전에 보여 준다.

## 교수자가 여는 리그

리그는 경기방과 여러 라운드를 묶는 운영 단위다. 기존 tw2의 `solo / duel / ffa`는 **한 경기의 모드**이며 리그와 다른 축이다. 교수자는 개인별 동일 과제를 수행하는 리그, Red/Blue 팀 대항 리그, FFA 라운드 등을 구성할 수 있다.

1. 교수자가 기관·강좌/분반, 리그 이름, 시나리오와 버전, 모집 인원, 팀/역할, 라운드 수, 시간·힌트·재제출·채점 정책을 설정한다.
2. 참가 링크 또는 회전 가능한 입장 코드를 발급한다. 코드는 방을 찾는 수단이며 계정·기관·분반·구매 권한을 대신하지 않는다.
3. 학생은 로그인 후 참가하고, 교수자는 참가 승인·팀 구성·역할 배정을 확인한다. 중복 참가, 다른 기관 참가, 정원 초과는 서버에서 차단한다.
4. 참가자와 실습 환경의 준비 상태가 확인되면 교수자가 라운드를 시작한다. 준비 실패 환경은 점수를 받는 경기에 포함하지 않는다.
5. 미션별 답안 등록과 채점이 진행된다. 교수자는 제출 현황과 환경 상태를 보고, 점수 공개는 리그 설정을 따른다.
6. 마감 시 서버 시각으로 제출을 닫고 이미 접수한 채점 작업을 완료한다. 이의 검토 후 결과를 확정하고 보고서·피드백을 제공한다.

리그 상태: `draft → open → preparing → running → grading → review → closed`, 별도로 `cancelled`. 라운드 중지·재개는 남은 시간을 서버가 기록하며 브라우저 카운트다운을 권위 값으로 쓰지 않는다. 접속이 끊겨도 초안과 접수된 제출은 보존한다. 종료·취소 후 타깃을 정리하고 증거·점수 보존 정책은 별도로 적용한다.

## 데이터와 tw2 연결

| 소유 영역 | 설계 엔터티 | 핵심 내용 |
|---|---|---|
| Core 아카데미 | 차시 노트·블록·캡처·수정 이력 | 현재 구현, 사용자 개인 기록 |
| Live Fire | TrainingRun | 기관·시나리오 버전·개인/리그 출처·실행 환경·tw2 battle ID |
| 리그 운영 | League / Round / Membership / Team | 교수자, 분반, 정원, 참가 상태, 역할, 라운드 정책 |
| 제출 | MissionDraft / Submission | 미션·역할·작성자·초안 버전, 등록 시각, 불변 답안·첨부 스냅샷, 중복 방지 키 |
| 채점 | Assessment / ScoreEvent | 제출 ID, 루브릭·채점기 버전, 점수·근거·재채점 이력 |
| 화면 조회 | LearningSummary / LeagueStanding | 실제 실행·저장 자료에서 만든 개인 진행 및 공개 순위 |

참조 엔진: tw2 `324d91fb22fee2c76051d5e73b58aa7f82de3e4c`. `Battle`에 `mode`, `cohort_id`, 참가자와 인프라 연결이 있으며, 강좌·분반·팀은 Cohort 구조를 활용할 수 있다. 이 저장소에 독립적인 두 번째 채점 엔진을 구현하지 않는다. 리그 운영 어댑터가 실행 예약과 참가 권한을 관리하고 실제 경기·제출·Assessor·채점은 기존 엔진 계약에 연결한다. 리그 전체가 이미 tw2에 구현되어 있다는 의미는 아니다.

현재 콘텐츠의 Purple 2개 미션은 tw2의 Blue 4·5단계에 저장되어 있다. 표시 역할과 런타임 side를 분리하여 누락을 막고, 점수 표에는 Red 35 / Blue 45 / Purple 20을 보여 준다. 기존 엔진의 Blue 합계는 65다. 리그 팀 편성에도 이 매핑을 명시하며 별도 Purple 참가자 역할을 지원하려면 엔진 계약 변경을 먼저 검증한다.

시작 시 콘텐츠 해시·루브릭·배점·점수 합산·재시도·동점 기준을 고정한다. 리그 중 콘텐츠 변경은 다음 리그부터 적용한다. `TUBEWAR_AUTO_SCORE=0`을 유지하고, 경보 존재나 임시 저장만으로 점수를 주지 않는다. 정식 등록한 답안과 해당 배틀의 증거를 함께 의미 평가한다. 중복 요청은 같은 제출 ID를 반환하고, 채점 재시도와 지연 응답이 점수를 두 번 반영하지 않도록 한다. AI 평가 실패는 미채점 상태로 남기고 교수자 검토·재채점 기록을 보존한다.

## 권한과 운영 경계

- C7의 기관·티어·콘텐츠 구매 권한을 시작·참가·제출 시 서버에서 확인한다. 무료 강좌 열람 권한이 Live Fire 실행 권한을 부여하지 않는다.
- 개인·팀·리그별 타깃 네트워크, Assessor 증거, 파일과 점수 조회를 분리한다. 교수자는 담당 리그 자료만 열람하며 학생의 개인 아카데미 노트는 자동 공유하지 않는다.
- 경기가 시작된 뒤 만료·정지된 권한은 상태별 정책으로 처리한다. 새 실행을 막되 기존 자료 열람·내보내기·안전한 종료는 유지한다.
- 동시 실행 자원은 생성 전에 예약한다. 대기열·실패·정리 상태를 노출하고 정원만으로 VM 자원을 무제한 할당하지 않는다.

## 구현 순서와 수락 조건

1. tw2 실행·미션 초안·등록·채점 계약 어댑터와 개인 훈련부터 연결한다. 재접속·중복 제출·잘못된 미션/역할·다른 배틀 증거를 검증한다.
2. 교수자 리그 생성, 초대, 참가 승인, 팀/역할, 준비 확인을 연결한다. 타 기관 코드 사용과 학생의 교수자 기능 접근을 검증한다.
3. 라운드 수명주기·시간 종료·실행 복구·불변 제출·점수 합산을 연결한다. 네트워크 단절·종료 직전 제출·채점기 재시작·취소를 검증한다.
4. 순위 공개·피드백·이의 검토·보고서·환경 정리를 연결한다. 6·7층에는 이 단계에서 실제 실행/리그 상태를 추가한다.

이번 작업은 위 설계와 현재 등록 콘텐츠·개인 노트 현황 표시까지다. 리그 생성/참가 버튼, 실제 경기 실행, AI 채점은 구현하지 않는다.
